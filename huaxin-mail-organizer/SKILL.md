# 华鑫邮件整理

用于用户要求在华鑫证券 Coremail 当前邮箱中查找、下载并整理估值表或其他附件时。只操作用户在 Codex 内置浏览器中当前打开的华鑫邮箱；不擅自发送、转发或回复邮件。

## 邮箱界面操作

- Coremail 的搜索、打开和阅读邮件、查看附件及下载附件，必须通过 Codex 内置浏览器中的可见页面，使用 Computer Use 操作。
- 优先复用现有 Coremail 标签；不得按搜索词、邮件或附件新开标签。如果没有可用的 Coremail 标签，最多在 Codex 内置浏览器中打开一个；若需要用户登录或恢复页面，停下来请用户处理，不要改用其他浏览器。
- 不通过外部浏览器、浏览器 Cookie、CDP/开发者工具、注入脚本、后台接口或直接 HTTP 请求绕过可见页面操作。若 Computer Use 无法完成某一步，说明具体阻塞并向用户确认，不要静默切换到其他访问方式。
- 下载后的本地文件检查、解压、哈希去重和归档仍使用合适的文件工具；这些本地处理不需要通过 Computer Use 操作。
- 搜索、翻页或打开邮件后重新读取当前界面状态，再继续操作，避免使用过期的界面元素。

## 任务启动

仅当本 Skill 用于实际邮箱查找或附件整理时执行本节；用户只是询问或维护 Skill 时，不启动邮箱登录流程。

1. 开始处理前，主动用一条简短消息收集三项信息：
   - 本次要查找什么（产品/基金名称或代码、日期范围、文件类型或科目级别等）。
   - 下载路径和目标文件夹名称。说明默认自动在桌面新建并使用 `邮件附件整理` 文件夹（`~/Desktop/邮件附件整理`）；用户没有特别要求时自动采用此默认值。
   - 是否有补充文件（例如 Excel 清单，可提供文件或路径），以及其他特殊要求。
   用户已明确给出的信息先简要复述为当前理解，只追问缺失或有歧义的内容；不要重复盘问已明确事项。目标目录不存在时创建；若默认目录或用户指定目录已存在，先清点内容并遵守不覆盖无关文件的规则。
2. 同时检查 Codex 内置浏览器中的现有页面并复用 Coremail 标签。若没有已登录的 Coremail 页面，则在该内置浏览器中打开 `https://mail.shchinafortune.com/coremail/`，由邮箱站点进入登录流程。不得自行拼接 `sid` 会话参数，也不得为登录另开重复标签。
3. 需要登录时，停在登录页面等用户自行完成登录或验证；不要索取或代填密码、验证码。Computer Use 确认页面已进入邮箱且查找范围已明确后，自动开始任务，不再额外询问是否开始。若关键范围仍未明确，则等用户补充后再查找。

## 修改 Skill 名称

若用户要为自己的副本重命名，使用 `scripts/rename_skill.py` 一次性同步文件夹名、`SKILL.md` frontmatter 中的 `name`、`agents/openai.yaml` 默认提示里的 `$skill-name`，以及 README 中的安装示例。Finder 手动改名不会触发自动同步；若用户已手动改过文件夹，可对当前文件夹运行脚本完成内部同步。若新名称已被同目录下其他 Skill 占用，脚本会停止且不覆盖目标。

## 核心规则

- 日期以估值表正文、附件名称或表内“估值日期”为准，不把邮件收发日期当成估值日期。
- 去重的基本单位是“基金身份 + 估值日期”。7.31 和 8.31 是两个不同批次，不能跨日期互相覆盖。
- 同一基金、同一估值日期只保留一个最终估值表。
- 同一内容同时有 Excel 和 PDF 时只保留 Excel（`.xls` 或 `.xlsx`）；没有 Excel 时才保留一个 PDF。优先保留明确对应目标基金、目标估值日期和目标科目级别的文件。
- 用户要求四级估值表时，不能用三级表替代；找不到目标级别要报告缺失。
- 最终整理文件夹不得放压缩包（`.zip`、`.rar`、`.7z` 等）。收到压缩包时先解压，核对其中的基金名称/代码和估值日期，只把需要的实际估值表放入目标文件夹。

## 工作流程

1. 按启动流程确认查找范围、补充文件和保存位置；无特别保存要求时在桌面创建并使用 `邮件附件整理` 文件夹。若目标文件夹已存在，先列出当前文件，不覆盖无关文件。
2. 在当前 Coremail 邮箱内按基金名称、产品代码、估值表关键词以及常见日期格式搜索。必要时打开邮件正文和附件名称核对，不能只按邮件发送日期筛选。
3. 下载附件到临时目录。压缩包只作为临时输入：用安全的临时解压目录展开，检查文件清单和路径，避免把压缩包本身或无关文件放进最终文件夹。
4. 对候选文件按“基金身份 + 估值日期”分组。每组按以下顺序选择：目标科目级别准确；Excel 优先于 PDF；内容和日期明确；文件可正常识别/打开。重复的同格式文件只留一份，必要时用文件哈希和大小辅助判断。
5. 将选定文件复制或移动到目标文件夹，使用清晰且不冲突的文件名。临时下载文件和解压目录在确认复制成功后清理；不要删除用户原始邮件附件。
6. 完成后复核：每个基金/日期是否恰好一份、是否误留 PDF 或压缩包、文件类型和估值日期是否正确、压缩包内表格是否已经单独落盘。对缺少实际附件的基金明确列出，不用虚拟净值、邮件正文汇总或其他日期文件冒充估值表。

## 去重和冲突处理

如果目标文件夹中已有同基金同日期的 PDF 和 Excel，保留 Excel 并移除重复 PDF；如果有多个 Excel，保留与目标科目级别和估值日期最明确、内容完整且可正常打开的一份。删除或替换前先确认文件确属重复，避免误删不同日期、不同科目级别或不同基金的文件。无法安全判断时保留候选并报告冲突，不凭文件名猜测。

## 交付报告

报告应简要列出：已找到并归档的数量、每个缺失或冲突的基金、实际保留的文件格式、是否解压过压缩包，以及目标文件夹链接。只有在逐项核对完成后才能说“全部齐了”；搜索不到附件不等于已经完成。
